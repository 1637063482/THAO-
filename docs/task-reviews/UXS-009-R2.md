### Medium — Sync-status transitions lose the active Chinese locale

- **File:** `src/js/savings-view.js:29-33`; `src/js/main.js:91-98`.
- **Evidence:** `setSavingsStatus()` selects its label locale from `root.dataset.locale`, but `refreshSavingsView()` never sets that dataset property on `#savings-root`. Its fallback is `vi`, so a Chinese-rendered page changes to Vietnamese whenever queued/syncing/synced/error status is updated.
- **Impact:** A required vi/zh state becomes inconsistent during normal saving.
- **Minimum correction:** Retain the active locale for status-node updates and add a Chinese interaction assertion for at least one lifecycle transition.

### Medium — No test proves the actual lifecycle bridge

- **File:** `tests/unit/savings-view.test.js`.
- **Evidence:** The only new test verifies a validation error callback preserves DOM values. It does not instantiate/drive `installSavingsSyncBridge()` or assert queued, syncing, synced, and error labels from changes to the real sync-status element.
- **Impact:** The claimed correction for R1's false sync states is not verified on its production bridge path.
- **Minimum correction:** Add focused DOM tests that mutate the sync indicator through success and failure classes and verify all four savings statuses, without falsely reporting success on failure.
