## Findings

### High - Required visual evidence remains isolated from the delivered home page and does not prove quick entry or privacy masking

- **Files/lines:** `docs/review-evidence/assets/UXS-004/viewport-360.png`; `viewport-1920.png`; `docs/review-evidence/UXS-004.md:111`; `index.html:165-173`; `TASK_PLAN.md:206,208-209`; `REVIEW_PLAN.md:121,130`.
- **Evidence:** I independently inspected the regenerated 360px and 1920px PNGs. They display an isolated dashboard component with synthetic figures, not the rendered application page: neither screenshot contains the header, navigation, legacy page, or quick-add control. The 360px first screen therefore cannot prove the required hero plus quick-entry access. Neither capture enables privacy mode or shows blurred/masked amounts; evidence merely points to the `blur-sensitive` class. The required 390/430/768/1440 captures have the same isolated component-only framing.
- **Impact:** The required six-width visual check still cannot establish production-page information priority, quick-entry reachability, responsive integration, or privacy masking.

### Medium - R5 tests wrappers rather than the real local-save and month-switch behavior, and do not assert a changed hero value

- **Files/lines:** `src/js/main.js:80-83,174-181`; `src/js/dashboard.js:115-120`; `tests/unit/dashbaord.test.js:72-89`; `docs/task-reviews/UXS-004-R4.md` Minimum Correction 2.
- **Evidence:** `main.js` routes its debounce and `switchMonthTab()` through two new functions, each containing only `initDashboard()`. The test invokes those exported helpers directly, asserts only that `.dashboard-hero` is non-null, and does not trigger the input debounce or `switchMonthTab()`. It also does not compare the hero value before and after an entry/month change.
- **Impact:** The specific stale-dashboard regression is not behaviorally protected; the test would pass if the production call sites stopped invoking these wrappers or if the hero rendered stale data.

### Medium - Evidence remains self-contradictory about screenshot provenance

- **Files/lines:** `docs/review-evidence/UXS-004.md:98-99,111`.
- **Evidence:** The retained “Known Limitations” says screenshots use injected synthetic HTML and are not the live `initDashboard()` path. The R5 paragraph says the same six PNGs were regenerated through `dashboard.js` with no injected HTML. Both statements refer to the submitted visual evidence, without a superseding correction or per-asset provenance.
- **Impact:** The audit record does not give a single verifiable account of how the reviewed PNGs were produced.

### Medium - Locale modules remain modified outside the Task's allowed file list

- **Files/lines:** `src/locales/vi.js:119`; `src/locales/zh-CN.js:119`; `TASK_PLAN.md:199`.
- **Evidence:** The full `c252742..04dd5bf` diff changes both locale files by adding an empty `// Dashboard` section, while the Task's explicit modified-file list does not include either module. No approved Task-plan amendment is present.
- **Impact:** Even comment-only changes violate the repository's exact current-Task scope rule and must be removed rather than retained as unrelated churn.
