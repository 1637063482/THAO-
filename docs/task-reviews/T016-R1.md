## Findings

### High

1. Re-entering the displayed CNY value can leave the DOM raw value and persisted VND fact different.
   - Evidence: each CNY `input` event immediately converts and writes to `state.appState.entries` / `state.pendingUpdates.entries` at `src/js/main.js:61-87`. On focusout, `parseCurrencyInputToVnd()` deliberately returns the pre-focus VND raw when the input text equals the pre-focus rendered CNY text (`src/js/currency-view.js:15-21`), but `src/js/main.js:103-122` only updates `dataset.raw` and the visible value; it never reconciles `state.appState` or `state.pendingUpdates`. `triggerCloudSave()` schedules the pending state at `src/js/main.js:87` and `src/js/sync.js:108-110`.
   - Reproduction: start with raw VND `1234` at automatic rate `3500`; focus displays `0.35`. A user can select/re-enter that visible `0.35`, causing the input listener to write `0.35 * 3500 = 1225` to state/pending. The focusout helper then identifies `0.35` as the unchanged display string and restores only DOM raw to `1234`. The reviewer executed the pure-path calculation: `input-state-vnd=1225`, `focusout-dom-raw=1234` (exit `0`). The queued state can therefore write `1225` while the UI reports `1234`.
   - Impact: a CNY display round-trip can silently corrupt a VND accounting fact and produces a state/DOM/Firestore-pending inconsistency. This violates the T016 requirement that VND remain the only persisted fact and that CNY round-trips not drift.
   - Missing test: `tests/unit/currency-view.test.js:98-112` covers focus/blur with no `input` event, but does not dispatch an input event that returns to the original displayed CNY string and then assert DOM raw, `state.appState`, and `state.pendingUpdates` all equal the original VND fact.
   - Minimum required change: give CNY direct-cell edits one authoritative persistence boundary. For example, defer the VND state/pending write until focusout, or atomically reconcile state/pending (and any queued save) whenever the focusout branch restores the previous raw fact. Add a direct-cell regression test for the sequence above; verify `dataset.raw`, `state.appState.entries[dataKey]`, and `state.pendingUpdates.entries[dataKey]` are all `1234`, with no interim drift sent for that no-op-equivalent result.

No Critical findings. No additional Medium or Low findings.
