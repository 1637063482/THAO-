## Findings

### High

1. `src/js/sync.js:173-184` treats a call to `HTMLAnchorElement.click()` as a successful local backup. That API only dispatches a browser download request: it has no success result or completion promise, and a blocked/cancelled/failed browser download does not necessarily throw. The import therefore continues to the destructive overwrite at `src/js/sync.js:226` after only a best-effort dispatch. `tests/unit/import-backup.test.js:58-66` injects a throwing mock, so it verifies the helper's catch branch but not the production download adapter's failure semantics. Impact: a user can lose the prior ledger when the intended recovery file was never persisted, directly violating the “backup failure must not overwrite” completion criterion. Minimum correction: make the production recovery adapter provide a verifiable successful local-persistence boundary before calling `writeLedger` (or refuse the overwrite when such confirmation is unavailable), and add tests that exercise that adapter's success and failure behavior rather than only an injected mock.

### Medium

1. `src/js/sync.js:156-161,206-227` serializes the remote current ledger after only coercing absent sections to `{}`; it never calls `validateLegacyImport` on the recovery payload. A corrupted/legacy snapshot with an invalid section type, key, or value can produce an invalid recovery file and still be followed by the overwrite. `tests/unit/import-backup.test.js:85-96` proves schema validity only for one already-valid fixture. Impact: the documented promise that a recovery artifact can be restored through the existing schema is not guaranteed. Minimum correction: validate the normalized recovery payload before download and before overwrite; treat invalid recovery content as a backup failure, and add the corresponding no-overwrite test.

2. `TASK_STATUS.md:13` and `docs/review-evidence/T018.md:7` record `470c430be75eb92b893dd5ef2b55da4db5fb6bc4` as the base SHA. `git cat-file -e` exits `128` for that value; the actual base is `470c43066906cb4b0856da6f22910d1f46f84f14`. Impact: the Task handoff and evidence cannot reproduce the stated diff range. Minimum correction: update both records to the resolvable base SHA and preserve the existing implementation head.

No Firebase deployment/Auth change, production-data operation, production backup collection, CNY/VND change, T011/T012 expansion, or unrelated refactor was found in the reviewed diff.
