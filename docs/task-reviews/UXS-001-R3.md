## Findings

### High — Nullable expected interest has no aggregation rule

- **Files/lines:** `UI_SAVINGS_REDESIGN_PLAN.md:337-340,359-362`; `docs/adr/004-ui-savings-boundary.md:69,91-92`.
- **Evidence:** The data contract now correctly permits `expectedInterestVnd: VND integer | null` and specifies that the UI displays `calculatedInterestVnd` for an individual null value. However, the product formula still defines “预计总收益” as the sum of `expectedInterestVnd` only. It does not define how a null value participates in that aggregate.
- **Impact:** UXS-010/012 can legitimately implement incompatible totals: exclude null deposits, coalesce them to zero, or use the calculated reference. This changes the primary savings/deposit summary while all implementations could claim compliance.
- **Minimum correction:** Define one null-safe aggregate formula in the UI plan and ADR-004. If the intended display fallback applies to totals, state `SUM(expectedInterestVnd ?? calculatedInterestVnd)` for eligible deposits; otherwise explicitly state the alternative and its user-visible meaning. Use the same wording in both documents.
