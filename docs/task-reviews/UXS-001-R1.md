## Findings

### High — Deposit schema does not define one persistable interest contract

- **Files/lines:** `UI_SAVINGS_REDESIGN_PLAN.md:346-356`; `UI_SAVINGS_REDESIGN_PLAN.md:455-483`; `docs/adr/004-ui-savings-boundary.md:63-86`.
- **Evidence:** The UI plan requires retaining both calculated and expected interest and allows a fixed-point rate *or* normalized decimal string. Its later shared schema, and ADR-004, specify only `annualRatePpm` and do not contain `calculatedInterestVnd`. ADR-004 also says rates are ppm only.
- **Impact:** UXS-010 and UXS-011 cannot implement one unambiguous persisted Deposit model or reference-interest formula. Implementations could persist incompatible rate representations or silently omit a required field.
- **Minimal correction:** Choose one contract and make all three locations agree: use `annualRatePpm` exclusively, define the ppm calculation/rounding, and explicitly state whether calculated interest is persisted (with a schema field) or derived at read time (with no persisted field).

### High — ADR-004 contradicts itself over whether `MATURED` is persisted

- **File/lines:** `docs/adr/004-ui-savings-boundary.md:76-77,88-91`; compared with `UI_SAVINGS_REDESIGN_PLAN.md:312-323`.
- **Evidence:** ADR-004's schema lists `MATURED` as an allowed stored `status`, then immediately says both `MATURING` and `MATURED` are derived and never persisted. The UI plan also treats both as Vietnam-date-derived states.
- **Impact:** UXS-010/011/013 may persist different status sets, producing incompatible summaries and reminder behavior after reload or date rollover.
- **Minimal correction:** Define the persisted enum and derived states exactly once, then use that same definition in ADR-004 and the UI plan. For example, if `MATURED` is derived, remove it from the persisted enum; if it is stored, define the write transition and stop calling it derived-only.

### Medium — Savings-goal representation is left ambiguous within the binding UI plan

- **File/lines:** `UI_SAVINGS_REDESIGN_PLAN.md:248-253,268-273` and `UI_SAVINGS_REDESIGN_PLAN.md:451-453`; `docs/adr/004-ui-savings-boundary.md:40-57`.
- **Evidence:** Sections 8.1/8.2 describe standalone month/year records with `period`/`year`, `targetVnd`, timestamps, and version, while the later binding schema and ADR-004 require 13 values in the existing yearly document's `settings` map. The earlier records are not labelled as a non-persisted ViewModel nor mapped to the 13 keys.
- **Impact:** UXS-007/008 has no single field-level storage contract for timestamps/version and could create the prohibited second target collection or incompatible settings shape.
- **Minimal correction:** Label the earlier structures as a derived ViewModel and map each field to `settings`, or replace them with the exact 13-key persisted schema and compatible metadata policy.

### Low — Duplicated architecture bullet introduced in the reviewed range

- **File/lines:** `ARCHITECTURE_PLAN.md:43,45`.
- **Evidence:** The identical client-layer bullet appears twice consecutively.
- **Impact:** No runtime effect, but it weakens the claimed reconciled architecture document.
- **Minimal correction:** Remove one duplicate line while performing the documentation-only rework.
