## Findings

### High - Required Dec 31 to Jan 1 continuity is not implemented

- Evidence: `src/js/streak.js:43-52` turns every eligible key into a date in only the supplied `year`; `src/js/streak.js:55-75` receives one `entries` object and can therefore never find a Dec 31 record from the adjacent annual ledger while calculating a Jan 1 streak. `src/js/render.js:155-156` supplies only `state.appState.entries` and `state.activeYear`.
- Reproduction: `tests/unit/legacy-streak.test.js:305-315` explicitly expects Jan 1 to be `1` despite a prior-year streak. `docs/review-evidence/T014_GREEN.md:183-185` confirms that Dec 31 to Jan 1 continuity was deliberately not implemented.
- Impact: a user who records on Dec 31 and Jan 1 receives a streak of `1`, not `2`; this violates T014's required cross-year boundary coverage and its entries-derived streak contract.
- Minimum required rework: provide the adjacent annual entries required for the boundary to the derivation/runtime, calculate Dec 31 to Jan 1 continuity from those entries, and add a passing cross-year test that expects `2`. Do not use the legacy `expense_streak` fields to fill the missing data.

### High - Remote snapshots recompute the panel but cannot trigger a 7/30-day milestone

- Evidence: `src/js/sync.js:121-123` calls only `window.renderStreakPanel()` after a snapshot. `src/js/render.js:171-189` derives and renders the number but has no milestone side effect. The sole milestone branch is `updateStreakAfterRecord()` at `src/js/render.js:192-204`, reached from direct input (`src/js/main.js:75-80`) and existing quick add (`src/js/quick-add.js:90-92`) only.
- Impact: when another device creates the seventh or thirtieth accounting day and this client receives the cloud snapshot, the visible streak updates but the required milestone does not fire. There is no remote-snapshot milestone regression test.
- Minimum required rework: route direct entry, quick add, and remote snapshot through one safe streak refresh/milestone path; preserve date-plus-threshold deduplication and add a snapshot test proving one 7-day and one 30-day milestone only.

### Medium - GREEN evidence has no immutable T014 implementation SHA

- Evidence: `docs/review-evidence/T014_GREEN.md:23-26` records the GREEN SHA as self-referential. `AGENT_WORKFLOW.md` explicitly prohibits this and requires a follow-up evidence correction with the exact SHA.
- Impact: the evidence cannot independently bind its GREEN claim to `08da24d0819b2a69f1bddb03446666853df873e7`.
- Minimum required rework: append or add a follow-up evidence correction that records the exact implementation SHA, then update `TASK_STATUS.md` to the resulting implementation/evidence head without rewriting this review.

### Low - Post-implementation workflow diff has a whitespace error

- Evidence: `git diff --check 08da24d..5eccbe0` exits `2` with `AGENTS.md:43: new blank line at EOF.` The T014 implementation range itself passes `git diff --check`.
- Impact: the current task branch does not satisfy a clean range diff after its post-implementation documentation commits.
- Minimum required rework: remove the trailing blank line in a focused documentation correction before requesting the next review.
