## Blocking findings

### High — Persisted status model contradicts accepted ADR-004

- **File:** `src/domain/deposit.ts:3,17-19,37,64-67`.
- **Evidence:** `DepositStatus` includes `MATURED`, `createDeposit()` accepts it as a stored status, and `transitionDeposit()` permits `ACTIVE -> MATURED`. Accepted ADR-004 states that only `ACTIVE | REDEEMED | ROLLED_OVER` are persisted and both `MATURING` and `MATURED` are read-time derived states. The current `MATURING` result also represents only the exact maturity date rather than the configured pre-maturity reminder window described by ADR-004.
- **Impact:** UXS-011 would encode an incompatible Firestore schema and UXS-013 could not correctly derive reminder-window state without redefining this domain contract.
- **Minimum correction:** Separate persisted and derived status types. Reject persisted `MATURED`; remove the `ACTIVE -> MATURED` transition; derive `MATURING` from the applicable reminder window and `MATURED` at/on or after maturity while the persisted status remains `ACTIVE`. Add boundary and invalid-persisted-status tests.

### High — Deposit summary includes handled and overdue records in the wrong totals

- **File:** `src/domain/deposit.ts:69-77`.
- **Evidence:** `currentPrincipalVnd` excludes only `REDEEMED`, so `ROLLED_OVER` principal is still counted and can double-count the replacement deposit. `expectedInterestVnd` is summed for every status, including `REDEEMED` and `ROLLED_OVER`. An overdue active deposit is also included in current principal and expected maturity total because the summary never consults the derived state. ADR-004 defines current principal and expected return over active/maturing deposits only and keeps matured-unhandled principal separate.
- **Impact:** The primary totals shown by UXS-012 can overstate both principal and expected return and can double-count rolled-over deposits.
- **Minimum correction:** Filter each aggregate by persisted plus derived status according to ADR-004. Exclude `REDEEMED`, `ROLLED_OVER`, and overdue `MATURED` records from current principal/expected-return totals; add tests for every status and the maturity boundary. If pending matured principal is required by the domain summary, expose it as a separate named total rather than mixing it into current principal.

### High — Interest year basis is inconsistent with ADR-004 and depends only on the start year

- **File:** `src/domain/deposit.ts:59-62`.
- **Evidence:** The denominator is `366` for every day of any deposit whose start year is leap, otherwise `365`. ADR-004 fixes the reference formula to `depositDays / 365`. For multi-year deposits, two equal-duration terms can therefore produce different reference interest solely because one starts in a leap year, even when most days fall in other years.
- **Impact:** Expected VND return is not calculated using the accepted product formula and can drift for multi-year terms.
- **Minimum correction:** Implement the ADR-004 fixed-365 reference formula, or stop and obtain a replacement ADR if an Actual/Actual convention is intended. Add leap-day and multi-year tests that make the chosen denominator explicit.
