## Blocking findings

### High — Remote snapshots leave the visible daily ledger stale

- **Files:** `src/js/render.js:50-66`; `src/js/sync.js:137`.
- **Evidence:** Realtime snapshots invoke `window.softUpdateDOM()`. That function updates only the legacy table elements by their `entry-...` IDs, then recalculates totals. It never calls `renderDailyLedger()`, while daily inputs have no IDs and are rendered only by `renderDailyLedger()`. Therefore, when the active view is daily, a remote snapshot can change `state.appState.entries` but the user continues seeing the previous daily-card values until a later full rebuild/toggle.
- **Impact:** This violates the required remote-snapshot consistency between the two views.
- **Minimum correction:** Refresh the derived daily view on the remote/soft-update path without overwriting focused unsaved input, and add a production-path test proving a remote snapshot updates the daily card while preserving pending local input behavior.

### High — Remarks can be erased from the derived view by render order

- **File:** `src/js/render.js:28-33`.
- **Evidence:** Only days having a remark create a `.daily-ledger-remark` element. The later loop indexes that filtered NodeList using the index of every `result.days` entry. If an earlier populated day lacks a remark and a later day has one, the later paragraph is assigned the earlier empty remark and the actual remark is blank.
- **Impact:** A source-backed legacy remark is not reliably shown in the daily view.
- **Minimum correction:** Bind each remark to its own rendered day (or iterate only remark-bearing days) and add coverage with at least one no-remark day before a remark-bearing day.

### High — Visual evidence does not match the reviewed implementation

- **Evidence asset:** `docs/review-evidence/assets/UXS-006/ledger-360x800.png`.
- **Evidence:** I inspected the supplied 360px capture. Its toggle displays the raw `ledger_view_toggle` key. The reviewed `index.html` instead hardcodes `Theo ngày / Bảng · 按日 / 表格`, and the reviewed codebase contains no `ledger_view_toggle` string. The image therefore cannot establish that the delivered revision rendered at the required viewport.
- **Impact:** The required responsive screenshot evidence is not trustworthy for the submitted head.
- **Minimum correction:** Regenerate all required viewport and landscape captures from the reviewed revision using synthetic state, confirm the actual toggle and both view defaults, and update evidence with reproducible command/exit-code and no-overflow checks.
