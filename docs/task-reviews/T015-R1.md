## Findings

### High

1. A PWA that remains visible while it crosses a Vietnam midnight does not refresh its current month, today row, quick-add target month, or streak until it later receives a `visibilitychange` or `focus` event.
   - Evidence: `refreshForLedgerDateChange()` is the only code that changes the active view for a ledger date boundary in `src/js/main.js:165-180`, and it is invoked only by the foreground visibility and focus listeners in `src/js/main.js:386-389`. There is no timer or other active-view boundary check. `openQuickAdd()` reads the new ledger day but constructs its choices from the still-stale `state.activeYear` and `state.activeMonthId` in `src/js/quick-add.js:14-21`; submitting consequently uses that stale month in its persistence key at `src/js/quick-add.js:49-61`.
   - Impact: for example, an actively visible February view at `2026-02-28T16:59:59Z` becomes March 1 in `Asia/Ho_Chi_Minh` at `17:00:00Z`. If the user opens Quick Add without first backgrounding/refocusing the PWA, the UI still has active month 2. No option matches March 1, so the browser selects the first February option, and recording it writes a February key rather than the current Vietnam date. The highlighted row and streak panel also remain stale. This violates T015's no-page-reload cross-midnight requirement.
   - Test gap: `tests/unit/local-date.test.js:74-93` manually changes `state.activeMonthId` from 2 to 3 before reopening Quick Add, and `tests/unit/local-date.test.js:122-146` dispatches `visibilitychange`. Neither reproduces a continuously visible PWA with no lifecycle event.
   - Minimal requested change: arrange a ledger-midnight refresh while the app remains visible (for example, schedule the next `Asia/Ho_Chi_Minh` boundary and reschedule after refresh), or otherwise guarantee that opening Quick Add and the visible table first synchronise the active ledger month. Add a fake-clock test that crosses midnight without dispatching `visibilitychange` or `focus`, then verifies the active month, today row, quick-add default/persistence key, and streak refresh.

No Critical findings. No additional Medium or Low findings.
