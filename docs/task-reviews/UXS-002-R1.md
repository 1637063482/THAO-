## Findings

### High - Reachable UI text remains hard-coded, so the Vietnamese-first complete-localization criterion is not met

- **Files/lines:** `src/js/quick-add.js:57,63,94`; `src/js/render.js:94-120,185-190`; `src/js/budget.js:86-90`; `src/js/sync.js:77,81,84`; `src/js/auth.js:61`; `src/js/charts.js:48`.
- **Evidence:** These paths still create user-visible Chinese validation toasts, budget text, table headings, streak copy, synchronization status, month labels, and the chart empty state directly rather than through `t()` or `data-i18n`.
- **Impact:** Default Vietnamese and a runtime Chinese/Vietnamese language switch cannot localize all reachable UI. This directly violates the UXS-002 objective and its required toast/validation/sync/empty/chart/auth-error coverage.

### High - Category chart labels are blank in the default Vietnamese locale

- **File/line:** `src/js/charts.js:109`.
- **Evidence:** `t(c.nameKey).replace(/[^一-鿿]/g, "")` removes every non-Chinese character. `t(c.nameKey)` is Vietnamese by default, so a valid Vietnamese category name becomes an empty string.
- **Impact:** Category chart legends/labels lose their names for the required default locale, despite both dictionaries containing valid Vietnamese category translations.

### High - Task Plan's exact allowed-file list prevents completion of its stated all-reachable-text objective

- **Files/lines:** `src/js/fireworks.js:479-541`; `src/js/currency-view.js:8`; `src/js/fx-display.js:53-56`; `TASK_PLAN.md:160-171`.
- **Evidence:** The unchanged reachable production paths contain Chinese congratulatory barrage text and CNY rate status strings. The plan requires replacement of *all reachable* hard-coded UI text, but its explicit modified-file list does not authorize changes to these files. Conversely, the implementation already changed out-of-list `src/js/export.js` and `tests/unit/csv-export.test.js` (see reviewed diff and `docs/review-evidence/UXS-002.md`), and `src/js/export.js:17-19,31,41-44` still has hard-coded Chinese CSV text.
- **Impact:** The Coder cannot safely make the necessary complete fix under the current plan; the existing out-of-scope change also breaches the single-Task file boundary. This is the blocking authorization conflict.

### Medium - i18n tests mock a reduced dictionary and do not prove the required state invariance

- **Files/lines:** `tests/unit/i18n.test.js:3-26,144-155`; `src/locales/vi.js`; `src/locales/zh-CN.js`.
- **Evidence:** The unit test replaces the real locale modules with eight-key mocks. Its state test only checks `document.documentElement.lang` and contains no actual state or `pendingUpdates` object snapshot/deep-equality assertion.
- **Impact:** The test suite can pass with missing real dictionary keys or a locale switch that mutates accounting/sync state. A separate reviewer structural check found both real dictionaries currently have 101 matching, non-empty keys, but that protection is not encoded in the Task-required tests.

## Minimum Resolution

1. The user must formally amend UXS-002's allowed-file list to include every confirmed reachable localization path required by the objective (at minimum `src/js/fireworks.js`, `src/js/currency-view.js`, and `src/js/fx-display.js`), and explicitly authorize or remove the existing `src/js/export.js` / CSV-test scope expansion. Alternatively, formally narrow the objective to exclude those surfaces.
2. After the plan is unblocked, replace the remaining strings above through the dictionaries; preserve Firebase, schema, amount/date, and design boundaries. Fix the Vietnamese chart-label transformation without using a Chinese-only character filter.
3. Extend tests to exercise the real dictionary key sets and to deep-compare a representative application state plus pending updates before/after locale switching. Re-run the required gates and return the Task to `READY_FOR_REVIEW`.
