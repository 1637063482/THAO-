## Blocking finding

### High — Remote refresh overwrites an active daily input's unsaved text

- **File:** `src/js/render.js:13-39, 64`.
- **Evidence:** `softUpdateDOM()` now calls `renderDailyLedger()`. When a daily input is focused, `renderDailyLedger()` records only its `data-key`, replaces `container.innerHTML`, and recreates that input from `state.appState.entries`. It restores focus and moves the caret, but does not retain the old input value or `data-raw`. A remote snapshot arriving while the user is editing therefore replaces their uncommitted daily text with the remote value.
- **Test gap:** The new test mutates `state.appState.entries` and checks `state.pendingUpdates`; it never focuses a daily input or gives it an unsaved DOM value. It cannot prove the claimed focused-input preservation.
- **Impact:** This violates the Task completion criterion that view/state handling must not lose unsaved input, and makes the R1 remote-refresh correction destructive during active daily editing.
- **Minimum correction:** Preserve the focused daily input's draft value/data before rebuild and restore it when its key remains present, without persisting it prematurely or defeating newer remote state for non-focused fields. Add a production-renderer test that focuses a daily cell, changes its DOM value without committing it, invokes the remote soft-update path, and verifies both focus and draft value survive while other daily cells use the remote snapshot.
