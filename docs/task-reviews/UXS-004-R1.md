## Findings

### High - Dashboard is dead code and does not redesign the actual home page

- **Files/lines:** `src/js/dashboard.js:75-90`; `src/js/main.js` (no `dashboard` import or `initDashboard()` call); `index.html` (no `dashboard-root` container); `docs/review-evidence/UXS-004.md:60-62`.
- **Evidence:** `initDashboard()` returns immediately if `#dashboard-root` is absent. The implementation diff does not modify `src/js/main.js`, `index.html`, or `src/css/app.css`, and a repository search finds no production caller or container. The evidence explicitly acknowledges that the UI is not wired into `main.js` or `index.html`.
- **Impact:** None of the requested hero, budget progress, spending awareness, category, streak, or recent-record UI is reachable by an application user. This fails the Task goal and its mobile-first completion criterion.

### High - The ViewModel reports an incorrect “today spending” value and hides over-budget remaining balance

- **Files/lines:** `src/js/dashboard-view-model.js:81-84,96-99`; `TASK_PLAN.md:202,204`.
- **Evidence:** For an `income` entry on the selected day, the code executes `todaySpending += val`; income is therefore displayed as today's spending. Separately, `Math.max(0, budgetVnd - totalSpending)` discards a negative remaining budget whenever spending exceeds the budget, while `isOverBudget` is true. The Task specifically requires an explicit negative hero value when over budget. Existing tests cover neither income-only/current-day spending nor an over-budget negative value.
- **Impact:** The two primary awareness figures can mislead the user: income is shown as expense and overspending is concealed as zero rather than a negative remaining balance.

### High - Required six-viewport visual evidence is absent

- **Files/lines:** `TASK_PLAN.md:206,209-210`; `docs/review-evidence/UXS-004.md:76-77`.
- **Evidence:** No files were produced under `docs/review-evidence/assets/UXS-004/`. The evidence itself states that screenshots at all six required widths have not been captured.
- **Impact:** There is no proof of mobile first-screen priority, long Vietnamese handling, privacy mask behavior, layout hierarchy, or overflow at 360/390/430/768/1440/1920.

### Medium - ViewModel reimplements budget and entry parsing rules, and the commit expands beyond the declared file list

- **Files/lines:** `src/js/dashboard-view-model.js:18-34,54-131`; `src/js/budget.js:8-15,110-115`; `src/locales/vi.js`; `src/locales/zh-CN.js`; `TASK_PLAN.md:199,203`.
- **Evidence:** The new ViewModel duplicates settings fallback, formula evaluation, month-key filtering, category aggregation, and day aggregation rather than consuming existing validated budget/entry derivations. It also changes locale files that are not in the Task's declared modified-file list. The repository workflow requires exact Task scope and requires stopping rather than self-expanding scope.
- **Impact:** A second budget/entry interpretation can drift from legacy behavior; the out-of-list locale changes need explicit planned scope or a minimal approved alternative.

## Minimum Correction

1. Wire the dashboard into the actual home page using the permitted `src/js/main.js`, `index.html`, and `src/css/app.css` files. Ensure it refreshes from the current legacy state without resetting year, locale, or pending updates, and preserve legacy table access.
2. Make today's spending sum expense categories only; return and render a negative `budgetRemaining` when over budget. Add RED/green tests for income-only today, mixed income/expense today, and an over-budget negative hero.
3. Refactor the ViewModel to consume the existing validated budget and legacy-entry derivations, rather than duplicating their rules. Keep legacy schema and budget policy unchanged.
4. Resolve the locale-file scope before returning: either obtain a Task-plan amendment or use already permitted localization mechanisms; do not leave unapproved file expansion.
5. Add anonymous/synthetic screenshots for 360/390/430/768/1440/1920 under `docs/review-evidence/assets/UXS-004/`, recording long Vietnamese, privacy mask, overflow, and information-priority checks.
