## Findings

### High

1. When automatic FX is unavailable with no valid cache, the production path leaves the existing default automatic rate (`3500`) usable for CNY conversion. `src/js/auth.js:66-70` only assigns `state.fxRateAuto` when `result.ok`; `src/js/state.js:15-18` initializes that value to `3500`; and `src/js/main.js:40-41` supplies it to every automatic CNY display/input conversion. The unavailable result changes only `#auto-rate-display` text. Independent probe confirmed `formatVndForCurrencyDisplay(3500, "CNY", 3500)` returns `1.00`, so users can still see and enter CNY values using an unverified default while the panel says the rate is unavailable. This violates T020's completion criterion that CNY is explicitly unavailable or a cache value when FX is completely unavailable. `tests/unit/fx-display.test.js:112-121` uses unrelated local `appState`/`pendingUpdates` objects and never traverses `auth -> state -> main` or verifies that CNY conversion is disabled/unavailable. Impact: users can create VND entries converted from an arbitrary automatic rate during a complete FX outage.

### Medium

1. `readCache` accepts any string as `updatedAt` at `src/js/fx-display.js:29-37`. If the cache timestamp is corrupt, `Date.parse` returns `NaN`, and the function returns the cached rate with `stale: false`. Independent probe with `{ rate: 3500, updatedAt: "not-a-date" }` and an HTTP 503 returned `{ ok: true, source: "cache", stale: false, updatedAt: "not-a-date" }`. This is not a verified cache timestamp and defeats the required cache-age/source/update-time reporting. There is no test for malformed cache timestamp data. Impact: a malformed or manually corrupted cache can be displayed as a fresh, valid CNY rate.

No Firebase deployment, Rules/Auth configuration change, production-data operation, transaction migration, third-party provider change, historical-ledger mutation, or T021 implementation was found in the reviewed range.

## Required Rework

1. In the actual `auth -> state -> main` path, represent unavailable automatic FX distinctly from a valid live/cache rate. When no valid cache exists, prevent automatic CNY display/input conversion from using the default or any unverified in-memory value; keep VND use available and show CNY as unavailable. Preserve explicit manual-rate behavior if it is still supported.
2. Treat cache records with an unparseable `updatedAt` as invalid and return unavailable/fallback rather than a fresh cache result.
3. Add production-path tests covering an initial/default automatic rate plus unavailable FX/no cache, asserting no automatic CNY conversion can occur, and covering a malformed cache timestamp. Retain existing timeout, valid-cache, and VND-persistence coverage.
4. Keep the rework within T020. Do not alter historical VND values, Firebase configuration/Rules/Auth accounts, production data, transaction migration, or T021.
