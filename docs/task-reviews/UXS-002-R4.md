## Findings

### High - R4 removes the localized budget label instead of rendering it once

- **Files/lines:** `src/js/render.js:94`; `src/js/main.js:229-230`; `src/locales/vi.js:146-147`; `src/locales/zh-CN.js:146-147`.
- **Evidence:** R4 replaces `t("monthly_budget", { month })` with a span containing only `monthId`. It adds dictionary key `budget`, but no production path calls `t("budget")`. `switchLanguage()` updates that same span only to `t("month_display", ...)`. The rendered heading is therefore only `T7` (Vietnamese) or `7月` (Chinese), without “Ngân sách” / “预算”.
- **Impact:** The required budget UI copy disappears in both locales. This is a user-visible regression and does not satisfy complete localization.

### Medium - No focused render test catches the budget-title content or locale switch result

- **Files/lines:** `tests/unit/i18n.test.js`; `src/js/render.js:91-105`.
- **Evidence:** The i18n tests cover dictionary keys and locale state but do not render the monthly table and assert one localized budget title before and after a language switch. The R4 regression passed all existing tests.
- **Impact:** A simple dictionary/render integration regression remains unguarded.

## Minimum Correction

1. In the existing budget-heading markup, render the localized month once and `t("budget")` once (or restore an equivalent single interpolation key); do not duplicate or omit the month/label.
2. Add a focused allowed-scope test proving the monthly-table budget heading is complete and switches correctly between `vi` and `zh-CN`.
3. Update the R4 evidence only as needed with the new test and fresh gate output, then return UXS-002 to `READY_FOR_REVIEW`. Do not start UXS-003.
