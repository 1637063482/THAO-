## Implementation Summary

- Added an import recovery path before overwrite writes.
- The app validates the selected import JSON first, asks for the existing overwrite confirmation, reads the current active-year ledger, serializes only `balances`, `entries`, and `settings`, computes a SHA-256 hash, and dispatches a local JSON recovery download before calling `setDoc(..., { merge: false })`.
- User cancellation exits before reading, downloading, or writing.
- Recovery download failure throws `BACKUP_FAILED` and exits before the overwrite write.
- Write failure occurs only after the recovery file has been generated, so the previous ledger can be restored through the existing import flow.
- No production backup collection, Firebase Rules, Auth account, real data migration, CNY/VND behavior, T011, or T012 code was changed.
