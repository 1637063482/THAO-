## R3 ADR-alignment rework

R2 RED reproduced five semantic failures: fixed-365 interest returned 50,000 instead of 50,137; the 30-day MATURING boundary remained ACTIVE; MATURED was accepted as persisted/transition state; handled deposits were included in totals; overdue principal was mixed into current totals. A second RED rejected prototype key `toString` as a persisted status.

- Persisted `DepositStatus` is now exactly `ACTIVE | REDEEMED | ROLLED_OVER`; `MATURING` and `MATURED` are derived-only.
- `deriveDepositStatus` accepts the applicable reminder-window days, derives MATURING before maturity, and MATURED on/after maturity.
- Summary includes only ACTIVE/MATURING principal and expected return, exposes overdue active principal separately as `pendingMaturedPrincipalVnd`, and excludes REDEEMED/ROLLED_OVER from current totals.
- Reference interest uses ADR-004 fixed-365 BigInt half-up calculation and remains capped at maturity.
- Runtime status validation uses own keys only, rejecting derived states and prototype property names.
